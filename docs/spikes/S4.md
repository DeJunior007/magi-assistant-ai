# Spike S4: wake word "Condessa"

Pergunta (design §12): quantas amostras o openWakeWord precisa para chegar a ≤ 1 falso disparo a
cada 2 h? Saída: modelo `condessa.onnx` e o limiar para `[satellite] wake_threshold`.

**Parte 1 (este documento):** kit de gravação, treino e avaliação em `tools/wakeword/`.
**Parte 2:** você grava, treina, joga 1 h e anota os números aqui.

Ativação: "Condessa", sozinha ou com "hey", "oi" ou "oh" na frente (o modelo dispara com a palavra
"Condessa" em qualquer forma). O nome da assistente continua MAGI ("Magui"). Todos os comandos
aceitam `--word` (padrão `condessa`): é o nome da pasta de dados e do `.onnx`.

## 1. Gravar (~15 min, uma vez)

```bash
uv run python -m tools.wakeword.record
```

Use o microfone de sempre (headset). Pode deixar o `magi-satellite` ligado: o PipeWire entrega o
microfone aos dois. A cada passo o terminal mostra o que falar e como. **Enter** grava, **r** +
Enter apaga e regrava a última, **p** + Enter pula, **q** + Enter sai. Se sair no meio, rodar de
novo continua de onde parou. As bordas de silêncio são cortadas sozinhas.

| Parte | O que você fala | Tempo |
|---|---|---|
| Positivas (54) | "Condessa", "Hey Condessa", "Oi Condessa" e "Oh Condessa" (alternadas) em 9 jeitos: normal, baixo, alto, rápido, lento, longe do mic, com jogo/música alta, cansado, rindo | ~6 min |
| Negativas (36 frases + 3×20 s) | Frases parecidas ("condensa", "confessa", "com dez", "promessa", "depressa", "a mesa", "comece", "conversa", "condição", "oi, vovó", "hey, Siri"), nomes de jogos e fala livre; "Condessa" nunca entra aqui | ~6 min |
| Ruído (60 s) | Nada: quarto como de costume (PC, ventilador) | 1 min |

Arquivos (WAV 16 kHz mono): `~/.local/share/magi/wakeword-data/condessa/{positive,negative,noise}/`.
Uma parte só: `--section positive|negative|noise`. Outro microfone: `--list-devices` e
`--device N`, ou `--target <source do PipeWire>`.

## 2. Treinar (CPU, ~5 min)

```bash
uv run python -m tools.wakeword.train synth                # ~150 clipes de TTS, ~US$ 0,07 (teto US$ 0,20)
uv run python -m tools.wakeword.train fetch                # 185 MB de negativos do openWakeWord (já baixado)
uv run --with onnx python -m tools.wakeword.train train    # grava ~/.local/share/magi/models/wakeword/condessa.onnx
```

- **synth:** `gpt-4o-mini-tts` (chave `openai-1` do keyring), 11 vozes × 8 estilos × 4 formas
  ("Condessa", "Hey Condessa", "Oi Condessa", "Oh Condessa"), pronúncia "con-DÊ-ssa". O gasto
  estimado fica em `wakeword-data/condessa/synthetic/spend.json` e o teto vale entre execuções
  (`--budget` muda). **Ouça 3 ou 4 clipes** em `synthetic/`: se a tônica estiver errada, apague a
  pasta e rode `synth --text "Condêssa"` (ou a grafia que soar como você).
- **fetch:** `validation_set_features.npy` (~11 h de fala, música e ruído já convertidos em
  atributos) do conjunto `davidscripka/openwakeword_features` no Hugging Face. 85% entram como
  negativos de treino; 15% ficam reservados para estimar falsos disparos por hora.
- **train:** separa 20% das suas positivas para avaliação (`wakeword-data/condessa/split.json`, fixo),
  cria 10 variações aumentadas de cada positiva (velocidade ±10%, reverb de sala, ganho −12..+6 dB,
  ruído do quarto/fala de fundo a 3–20 dB de SNR, ruído fraco para não haver silêncio digital),
  calcula os embeddings com os mesmos ONNX do satélite e treina uma MLP (16×96 → 64 → 64 → 1) em
  numpy. O modelo anterior vira `condessa.onnx.bak`. O pacote `onnx` só entra nesse comando
  (`--with onnx`), sem mexer no `pyproject.toml`.

Medido na parte 1 (12 núcleos, sem GPU, dados de teste com 10 clipes + os 103 mil negativos do
`fetch`): 69 s e 3,6 GB de RAM no pico. Com ~190 positivas o cálculo de atributos sobe para 1–2 min.

Opções úteis: `--aug` (variações por positiva), `--epochs`, `--neg-weight` (maior = menos falsos
disparos e menos acertos), `--extra outro.npy`.

### Por que não o treino oficial do openWakeWord

O caminho oficial (`openwakeword/train.py` com o notebook `automatic_model_training.ipynb`) gera
~50 mil clipes com o Piper (modelo `en_US-libritts_r`, só inglês), usa 2000 h de negativos
(`openwakeword_features_ACAV100M_2000_hrs_16bit.npy`, 17 GB) e treina em torch por horas; foi feito
para Colab com GPU, e sem GPU NVIDIA aqui fica inviável. A ideia central é a mesma (atributos
congelados + classificador pequeno com saída `[N, 1]`), então o modelo daqui carrega no satélite
igual a um modelo oficial. Se o modelo local não passar no critério, o plano B é o Colab:

1. Abra <https://colab.research.google.com/github/dscripka/openWakeWord/blob/main/notebooks/automatic_model_training.ipynb>
   e escolha *Runtime → Change runtime type → T4 GPU*.
2. Em `target_word` ponha `condessa` e rode as células de instalação e download (ACAV100M, MIT RIR,
   AudioSet, FMA: ~1 h).
3. Antes da geração, troque o gerador do Piper por clipes próprios: compacte
   `wakeword-data/condessa/positive/` e `synthetic/`, faça upload e aponte `positive_train`/`positive_test`
   do YAML para essas pastas (o Piper do notebook não fala português).
4. Rode o treino (`--augment_clips` e `--train_model`, ~1–2 h na T4) e baixe o `.onnx` gerado para
   `~/.local/share/magi/models/wakeword/condessa.onnx`.

## 3. Avaliar

Grave ~1 h de jogo normal (falando com amigos, jogo e música tocando) para medir falsos disparos
com áudio que o treino nunca viu:

```bash
mkdir -p ~/.local/share/magi/wakeword-data/condessa/eval
pw-record --rate 16000 --channels 1 --format s16 ~/.local/share/magi/wakeword-data/condessa/eval/jogo1.wav
# Ctrl+C ao terminar a sessão; evite dizer "Condessa" durante a gravação
uv run python -m tools.wakeword.evaluate
```

O `evaluate` passa o áudio em blocos de 80 ms pelo `OpenWakeWordDetector` do satélite (sem o portão
de energia, então é mais rigoroso que em produção) e mostra, para limiares de 0,10 a 0,95, a taxa
de acerto nas positivas reservadas e os falsos disparos por hora (recarga de 2 s, como o
`WakeSpotter`). Sugere o limiar de maior acerto com ≤ 0,5 falso/h.

**Critério do S4:** ≥ 95% de acerto **e** ≤ 1 falso disparo a cada 2 h (0,5/h).

Se não passar: mais negativos (grave mais `eval/` e copie para `negative/`, que entra no treino),
`--neg-weight 4`, mais positivas nos estilos que falharam (o `evaluate` lista as perdidas) ou o
plano B do Colab.

## 4. Usar no satélite

No `~/.config/magi/config.toml`:

```toml
[satellite]
wake_model = "condessa"      # nome em models_dir ou caminho de um .onnx
wake_threshold = 0.5         # use o sugerido pelo evaluate
```

`wake_threshold` vale na hora (recarga do config). `wake_model` só vale ao reiniciar:
`systemctl --user restart magi-satellite`. Para voltar ao provisório: `wake_model = "hey_jarvis"`.
