# Spike S2: atalho de apertar pra falar (PTT)

Pergunta (design §12): o KGlobalAccel entrega pressionar **e** soltar? O DualSense via evdev precisa
do grupo `input`?

Ambiente: Nobara (Fedora 44), KDE Plasma 6 / KWin 6.7.4 em Wayland, KF6 6.29, Python 3.12 (uv),
`dbus-next` e `evdev`. DualSense (054c:0ce6) pareado por Bluetooth (uhid). Usuário fora do grupo
`input`. Script: `spikes/s2_ptt.py` (`kga`, `evdev`, `cleanup`).

## Decisão

| Entrada | Mecanismo | Permissão extra |
| --- | --- | --- |
| Teclado | KGlobalAccel via D-Bus (`doRegister` + `setShortcutKeys`, sinais `globalShortcutPressed`/`Released` do componente) | nenhuma |
| DualSense | `python-evdev` lendo o nó "DualSense Wireless Controller" (hoje `/dev/input/event29`), **sem grab** | **nenhuma**: a ACL `uaccess` já vem do systemd |

**Não é preciso pôr o usuário no grupo `input` nem criar regra udev.** Os dois mecanismos alimentam a
mesma máquina de estados de PTT no satélite. Falta só o teste com a tecla e o botão de verdade (ver
"O que você precisa fazer").

## 1. KGlobalAccel (D-Bus)

O que foi feito (`uv run python spikes/s2_ptt.py kga --rounds 20`):

1. Introspecção de `org.kde.kglobalaccel`: no Plasma 6 o serviço roda **dentro do `kwin_wayland`**.
   A interface `org.kde.kglobalaccel.Component` tem os sinais `globalShortcutPressed(ssx)`,
   `globalShortcutReleased(ssx)` e `globalShortcutRepeated(ssx)` (componente, ação, timestamp em ms).
   **O sinal de soltar existe.**
2. Registro do componente temporário `magi-spike-ptt` / ação `ptt` com **Meta+Ctrl+Alt+F12** (livre no
   `kglobalshortcutsrc`): `doRegister(as)` + `setShortcutKeys(as, a(ai), u=SetPresent|NoAutoloading)`.
   Retornou a tecla aplicada; `getComponent` → `/component/magi_spike_ptt`, `isActive=true`.
3. `invokeShortcut("ptt")` 20 vezes, medindo do envio da chamada até a chegada do sinal.
4. Limpeza: `setInactive` + `unregister(componente, ação)` (→ `true`) + `Component.cleanUp()`.

Resultados:

| Item | Resultado |
| --- | --- |
| `globalShortcutPressed` | chega em 20/20 invocações |
| Latência chamada → sinal (D-Bus ida e volta) | mediana **0,53 ms**, mín 0,29, máx 1,16 ms (n=20) |
| `globalShortcutReleased` | existe, mas **`invokeShortcut` só emite Pressed** (nenhum Released depois) e manda timestamp `0`. Soltar só dá para confirmar com tecla física |
| Limpeza | `unregister` → `true`; o objeto `/component/magi_spike_ptt` some ~1 s depois; `~/.config/kglobalshortcutsrc` ficou **idêntico** ao backup feito antes do spike (`diff` vazio, nenhuma linha "magi-spike") |
| Meta+M (`magi-view.desktop`) | intocado |

A latência real da tecla física é a do KWin (evento de entrada → sinal) mais esse ~0,5 ms de D-Bus;
o modo `--listen` imprime o timestamp do evento para medir isso.

### Incidente: dois travamentos do KWin durante o spike

As duas primeiras execuções **derrubaram o `kwin_wayland`** (SIGABRT, 01/10 às 21:40 e 21:41). O KWin
reiniciou sozinho, mas o `plasmashell` reiniciou e o **Firefox fechou** (abriu o crashreporter).
Peço desculpas pelo transtorno.

Causa (pilha no `journalctl --user`): `operator>>(QDBusArgument, QKeySequence)` do
`libKF6GlobalAccel` lê **sempre 4 inteiros** do struct `(ai)` sem checar o tamanho. Mandei `(ai)` com
1 inteiro (primeiro em `globalShortcutsByKey`, depois em `setShortcutKeys`) e o libdbus abortou o
processo (`type invalid 0 not a basic type`). Como o KGlobalAccel vive dentro do KWin, cai o
compositor inteiro.

Regra para o satélite (tarefa da fase 1): **toda `QKeySequence` enviada por D-Bus vai como
`[tecla, 0, 0, 0]`** (`qkeyseq()` no script). Com isso o registro funcionou sem incidentes. Vale um
teste unitário que garanta o preenchimento até 4. Também evitar métodos que não sejam necessários
(`globalShortcutsByKey` etc.): para saber se a tecla está livre basta olhar o retorno de
`setShortcutKeys` (devolve vazio se houver conflito) ou o `kglobalshortcutsrc`.

### Notas para a implementação

- Ao sair, chamar `setInactive(actionId)` (o atalho fica registrado, mas o KWin para de capturá-lo).
  Não chamar `unregister` no uso normal, senão a tecla escolhida pelo usuário se perde.
- Ignorar `globalShortcutRepeated` (autorrepetição com a tecla segurada).
- O KWin captura a combinação: o jogo em foco **não** recebe a tecla. Para PTT em jogo, uma tecla
  única sem modificadores (ex.: Pause, Scroll Lock, F13–F24 ou botão lateral do mouse mapeado) é
  mais confortável que Meta+Ctrl+Alt+algo. A tecla padrão continua aberta (PRD); o kmix tem uma ação
  `push_to_talk` própria, sem tecla, então não atribuir a mesma tecla lá.
- Identidade do componente: usar nome fixo (ex.: `magi-satellite`), sem `.desktop`, para não
  colidir com `magi-view.desktop`.

## 2. DualSense via evdev

O que foi feito (`uv run python spikes/s2_ptt.py evdev`):

| Nó | Nome | Permissão | Legível sem grupo `input`? |
| --- | --- | --- | --- |
| `/dev/input/event29` | DualSense Wireless Controller | `crw-rw---- root:input` + ACL `user:pedrojr:rw-` | **sim** |
| `/dev/input/event30` | ... Motion Sensors | `crw-rw---- root:input`, sem ACL | não |
| `/dev/input/event31` | ... Touchpad | `crw-rw---- root:input`, sem ACL | não |

- A ACL vem do systemd: `/usr/lib/udev/rules.d/70-uaccess.rules` tem
  `SUBSYSTEM=="input", ENV{ID_INPUT_JOYSTICK}=="?*", TAG+="uaccess"`, e o `udevadm info` do event29
  mostra `ID_INPUT_JOYSTICK=1` e `TAGS=:seat:uaccess:`. O logind dá leitura ao usuário da sessão
  ativa. (As regras do `steam-devices` e do `nobara-controller-config` cobrem só o `hidraw`.)
- O event29 abre com `evdev.InputDevice` e expõe os botões `BTN_SOUTH/EAST/NORTH/WEST`, `BTN_TL/TR`,
  `BTN_TL2/TR2` (L2/R2 digitais), `BTN_SELECT/START`, `BTN_MODE` (PS), `BTN_THUMBL/THUMBR`.
  O botão de microfone e o clique do touchpad **não** estão nesse nó (o clique está no event31).
- Ler **sem `grab()`**: o jogo e o Steam Input continuam vendo o botão. Com grab o botão sumiria do
  jogo.
- Latência evdev: não medida (precisa de aperto físico). O modo `--listen` mede evento → leitura.
- O número `eventN` muda a cada reconexão Bluetooth: o satélite deve achar o nó por
  vendor/product (054c:0ce6) + nome "DualSense Wireless Controller" em `/sys/class/input` e
  reabrir quando o controle reconectar.
- Limite da ACL: vale para a sessão local ativa (inclui serviço `systemd --user`); some ao trocar de
  usuário ou de VT, o que não afeta o uso.

### Opções de permissão (documentadas, **nada foi alterado**)

1. **Nada a fazer (recomendado).** Os botões já são legíveis pelo `uaccess` padrão.
2. **Regra udev só para o DualSense**, se um dia precisar do touchpad (clique) ou dos sensores.
   O número tem de ser menor que 73 (`73-seat-late.rules` aplica o `uaccess`):

   ```bash
   echo 'SUBSYSTEM=="input", KERNEL=="event*", ATTRS{id/vendor}=="054c", ATTRS{id/product}=="0ce6", TAG+="uaccess"' \
     | sudo tee /etc/udev/rules.d/72-magi-dualsense.rules
   sudo udevadm control --reload
   sudo udevadm trigger --subsystem-match=input --action=change
   getfacl /dev/input/event30 /dev/input/event31   # deve aparecer user:pedrojr:rw-
   ```

   Desfazer: `sudo rm /etc/udev/rules.d/72-magi-dualsense.rules` e repetir o reload/trigger.
3. **Grupo `input`** (não recomendado): `sudo usermod -aG input pedrojr` e sair/entrar na sessão.
   Dá leitura de **todos** os dispositivos, inclusive o teclado (qualquer processo do usuário vira
   um keylogger em potencial). Não é necessário para o PTT.

## O que você precisa fazer / testar

1. **Tecla física (soltar):** rode `uv run python spikes/s2_ptt.py kga --listen 30` e aperte e
   segure **Meta+Ctrl+Alt+F12** algumas vezes. Esperado: um `globalShortcutPressed` e um
   `globalShortcutReleased` por aperto, com "segurou N ms" coerente. Repita com um jogo em tela
   cheia em foco (`--key Pause`, por exemplo, se a combinação for desconfortável). O script
   desregistra tudo no fim.
2. **DualSense:** rode `uv run python spikes/s2_ptt.py evdev --listen 30` e aperte/solte botões.
   Confira "pressionou/soltou" e a latência evento → leitura; escolha o botão de PTT.
3. **Decidir** a tecla padrão do PTT e o botão do controle (abertos no PRD).
4. **Grupo `input`:** recomendo **não** entrar. Só aplique a regra udev da opção 2 se quiser o
   touchpad/sensores.
5. Se alguma execução do `kga` for interrompida (Ctrl+C antes da limpeza ou queda), rode
   `uv run python spikes/s2_ptt.py cleanup`.

## Decisão do usuário (01/10/2026)

- Tecla de apertar pra falar: **Pause**.
- DualSense: **PS + Share segurados juntos** (`BTN_MODE` + `BTN_SELECT` no `hid-playstation`); grava enquanto os dois estiverem pressionados. Atenção na 1.3: a Steam usa o botão PS para atalhos próprios (chords e overlay), então conferir se segurar PS + Share não dispara nada da Steam.
- Grupo `input`: não entra; o DualSense já é legível via `uaccess`.
